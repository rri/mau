Sign-in, signup, and public profile, mock 1

Pick a screen below, or click through. Passkey prompts are simulated.

Screens

Approved decisions shown

  • Sign-in is a single passkey button, with links for a recovery code and (only when signup is open) creating an account.
  • Signing in with a recovery code forces adding a new passkey before anything else.
  • Signup: username and display name, then create a passkey, then recovery codes shown once. You must tick "I've saved these codes".
  • The first admin account needs the one-time setup link printed in the server log.
  • New users land on an empty Reading view with "Add your first book" and "Import".
  • The public profile shows display name, @username, and bio, then every published item. "Nothing shared yet" when empty.

Open questions for these screens

  1. What the sign-in page shows when signup is closed or invite-only. Mock: no "Create an account" link; a line says "New here? Ask for an invite link."
  2. Expired or used invite link. Mock: an explanation and "Ask whoever invited you for a new link."
  3. Username availability is checked as you type during signup. As mocked.
  4. Public profile layout: each published item is a section. Finished books and tags show a cover row (up to 8) with "See all", which opens the item's own page. Currently active shows progress bars. As mocked.
  5. Should the public profile show finish dates and pages? Mock: finish month and year; pages only on active books.
  6. Should the public profile have a small "mau" footer linking to the instance's sign-in page? Mock: yes.
  7. Recovery-code sign-in asks for your username as well as the code, so a code alone can't be tried against every account. As mocked.
  8. The setup link expires after first use, and also after 24 hours? Mock: first use only; a new one is printed on each restart until an admin exists.
