# Implementation decisions

Choices made while building mau that the spec (`docs/SPEC.md`) doesn't settle.
Each entry says what was chosen and why, so any of them can be revisited.
Newest entries at the bottom of each section.

## Milestone 1: skeleton

- **Port 8370** is the default listen port (`127.0.0.1:8370`).
- **Config lookup:** `--config`/`MAU_CONFIG`, else `/etc/mau/mau.toml` if it
  exists, else built-in defaults. Unknown keys are an error. `public_url` must
  be `https://…` or `http://localhost…` (passkeys need a secure context).
- **Development data** lives in `./data` (git-ignored).
- **Logging** via `MAU_LOG` (tracing env-filter syntax), default `info`.
- **Release profile:** thin LTO, one codegen unit, stripped.
- **SPA shell** is `200.html` (adapter-static fallback). The server serves
  matching embedded files, else the shell. `_app/immutable/*` is cached for a
  year; everything else `no-cache`.
- **Crates:** `mau-core` (pure domain logic, no I/O) and `mau-server` (binary
  `mau`).
- **npm audit** reports low-severity `deepmerge` advisories via
  `@sveltejs/adapter-static` (build-time only, not shipped). Left as is.

## Architecture (decided before milestone 2)

- **IDs** are UUIDv7 strings, generated by whichever side creates the record
  (clients create books, readings, copies offline).
- **Hybrid logical clock (HLC):** timestamps are strings
  `"{ms:013}-{counter:04}-{node}"`, so plain string comparison orders them.
  `node` is a random per-device ID (`srv` for the server).
- **Sync = operation log with field-level last-writer-wins.** Every synced row
  keeps a per-field clock (JSON column). A `set` operation updates a field only
  if its HLC is newer than that field's clock. Deletes are tombstones; later
  operations on a tombstoned row are dropped.
- **Progress uses a fork-aware rule** (to get "latest position wins, and the
  losing device's taps vanish"): each progress operation carries the HLC of the
  position it started from (`base`). If its HLC is older than the current
  position's, it's dropped. If `base` matches, it's appended. If `base` is
  older (the other device moved on meanwhile) and this operation is newer, the
  events recorded after `base` are deleted before appending.
- **Pull** uses a per-user change sequence: every row change bumps a global
  `seq`; clients ask for rows with `seq > last_seen`.
- **Manual ordering** uses fractional-index strings (`rank`), compared as
  plain strings. The display is active books by rank, then inactive by rank, so
  "end of active" and "top of inactive" are just ranks after the last active or
  before the first inactive.
- **The browser keeps the whole library in IndexedDB** and renders from it;
  the server is only needed for catalog search, ISBN lookup, import, admin,
  and sharing changes.
- **Public profile and share pages are rendered on the server** (HTML, no
  JavaScript needed) so search engines can index them, using the `maud` crate.
- **API types** are generated from Rust into TypeScript with `ts-rs`.

## Milestone 2: authentication

- **Discoverable passkeys are required at registration.** webauthn-rs's
  `start_passkey_registration` asks for `residentKey: "discouraged"`; mau
  rewrites that to `"required"` before sending it to the browser. Without this,
  hardware keys like YubiKeys create non-discoverable credentials that the
  username-less "Sign in with a passkey" button can't use.
- **Sign-in is a modal prompt, not autofill.** webauthn-rs's
  `start_discoverable_authentication` sets `mediation: "conditional"`
  (autofill UI); mau clears it so the button opens the normal passkey prompt.
- **Ceremony state** (in-progress registrations and sign-ins) is kept in
  server memory for 5 minutes, keyed by a random challenge ID. A restart
  during a sign-in just means trying again.
- **Session cookie:** `mau_session`, 32 random bytes, base64url. Only its
  SHA-256 is stored. `HttpOnly`, `SameSite=Lax`, `Secure` unless `public_url`
  is `http://localhost`. The 30-day expiry is extended at most once an hour.
- **CSRF:** besides SameSite, every non-GET `/api` request must carry an
  `Origin` header matching `public_url`.
- **"Fresh passkey" for sensitive actions** means the session confirmed a
  passkey within the last 5 minutes (`/api/auth/reauth`).
- **Recovery codes:** format `xxxxx-xxxxx` from a 31-letter alphabet without
  look-alikes (no 0/o/1/l/i), about 49 bits each. Stored as Argon2id hashes.
- **Tokens** (invites, setup link, admin enrollment links) are 32 random bytes;
  only SHA-256 hashes are stored. The setup token exists only in memory.
- **A recovery-code sign-in** creates a restricted session that can only add a
  passkey; it becomes a normal session once one is added. The same applies to
  admin-issued enrollment links.
- **Device labels** for sessions and suggested passkey names come from the
  User-Agent ("Firefox on Linux").
- **Passkey ceremonies aren't unit-tested end to end.** webauthn-rs's soft
  authenticator can't create discoverable credentials, so the full
  register/sign-in flow is covered by Playwright with Chromium's virtual
  authenticator (milestone 8). API tests cover everything around it.
- **Generated TypeScript types** go to `web/src/lib/api/generated/` (set in
  `.cargo/config.toml`), refreshed by `cargo test`. They're committed so the
  web app builds without running Rust tests first.
- **Deleting the last admin's account is refused** ("make someone else an
  admin first"), extending the spec's "last admin is protected" to self-deletion.
- **Imports use explicit extensions** (`#lib/api/client.ts`), as the SvelteKit
  3 template's `package.json` "imports" mapping requires. ts-rs is told to
  emit `.ts` extensions too (`TS_RS_IMPORT_EXTENSION`).
- **End-to-end tests start their own server** on port 8371 with a temporary
  data directory, and read the setup link from its log. They use Chromium
  (Playwright) because only Chromium offers a scriptable virtual authenticator.
- **Who's signed in is cached in localStorage** (`mau.me`) so the app opens
  offline; the server's answer always wins when it's reachable.
- **Routes:** signed-out pages under `src/routes/(public)`, the app under
  `src/routes/(app)` with the tab bar (bottom on phones, left sidebar from
  900px wide).

## Milestone 3: library, sync, Reading view

- **Progress conflicts are judged per chain, not per tap.** A device's unsynced
  progress changes form a chain (each one's `base` is the previous one's
  clock). The server judges the whole chain by its newest change against the
  current position: older chains are dropped whole; newer chains that branched
  from an older position replace the other branch's events after that point.
  Judging tap by tap would drop the early taps of a winning session.
- **Undo is an operation** (`progress.undo`) that removes the event it undoes
  and restores the position, so undone taps never count as reading.
- **One change number per sync request.** All rows a request changes share
  one `seq`, taken first so the transaction holds SQLite's write lock.
- **Each operation runs in a savepoint;** an invalid operation is rolled back
  and reported under `rejected`, and the device discards it. Operations about
  deleted or unknown rows, or with stale clocks, are `dropped` silently.
- **Removing a book** tombstones its readings, events, copies, and tags in
  the same operation (the spec's "permanently deletes"), and blanks its notes
  and rating. Tombstone rows stay so other devices learn about the removal.
- **Seed data:** `mau seed --user NAME` (or `just seed NAME`) adds the mocks'
  16 books with generated reading history. It refuses unless `public_url` is
  `http://localhost…`.
- **Dates for progress events** are computed by the device in the user's time
  zone setting and stored as `YYYY-MM-DD`.
- **Undoing "start reading"** deletes the new reading (`reading.delete`), so an
  undone start or re-read leaves no empty reading behind.
- **The browser keeps two layers:** the last data the server sent (in
  IndexedDB, one database per user: `mau-<user id>`) and the unsent
  operations (an outbox). The screen shows the server data with the outbox
  replayed on top, using the same rules as the server. After each sync the
  view is rebuilt from the server's answer plus whatever is still unsent.
- **Sync timing:** 0.8 s after the last change, when the browser comes back
  online, when the tab becomes visible, and every 60 s. Up to 500 operations
  per request.
- **A revoked session** (the server answers 401 to a sync) wipes this device's
  copy, including unsent changes, and goes to sign-in (spec assumption 3).
- **Rejected operations** are discarded and the first reason is shown in a toast.
- **The service worker** caches the app shell and assets at install, serves the
  cached shell for page loads when offline, and caches cover images as they're
  seen. It never caches `/api` (data lives in IndexedDB) or the server-rendered
  public pages (`/u/…`, `/s/…`). In SvelteKit 3 it's excluded from the main
  `tsconfig.json` and checked with `tsconfig.service-worker.json`.
- **"Today"** is computed in the user's time zone setting, not the device's.
- **Finished books leave the Reading view at once** (spec decision); the undo
  toast brings them back.
- **Status line:** the Reading header says "Offline · N unsynced" or
  "Syncing…" when relevant, and nothing otherwise.

## Milestone 4: catalog and book detail

- **Surname for the author sort:** the last word of the first author's name,
  plus particles directly before it (le, de, van, von, der, du, da, di, …), so
  "Ursula K. Le Guin" sorts under "Le Guin". "St." is a particle only when it
  comes right before the last word ("Emily St. John Mandel" sorts as "Mandel").
- **Catalog layout and sort** are remembered per device in localStorage
  (`mau.catalog.layout`, `mau.catalog.sort`); filters reset on each visit.
- **"‹ Catalog"** uses browser history when you came from the catalog, so its
  scroll position and filters are kept; otherwise it's a plain link.
- **Edit details** takes authors as one comma-separated field. Entering the
  catalog's own value clears that override instead of storing a copy.
  "Reset to catalog" clears title, authors, and cover overrides together.
- **Uploading a cover needs a connection** (the image goes to the server);
  title and author edits work offline.
- **Notes autosave** 0.7 s after typing stops.
- **Calendar shading** uses one teal ramp mixed from the accent color, so it
  follows light and dark mode automatically.
- **Daily summaries** merge consecutive forward moves on the same day into
  one line; any backward move is its own "moved back" line.
- **A re-read** starts with the previous reading's total; it can be changed
  by tapping the page count.

## Milestone 5: adding books, providers, covers

- **HTTPS client:** reqwest with rustls (aws-lc-rs) and the system's
  certificate store; needs `cmake` and a C compiler at build time.
  User-Agent `mau/<version> (+<public_url>)`, 20 s timeout.
- **Provider fallback:** enabled providers are asked in the admin's order;
  for a text search the next one is asked when fewer than 3 results came back
  ("thin"), and results are de-duplicated by title and first author, up to 20.
  For an ISBN, the first provider with a match wins.
- **Provider responses are cached 30 days** in `provider_cache` (search
  results, ISBN lookups, edition lists, and each offered search result).
  Adding a book uses the cached result, so clients can't inject catalog data.
- **What a work brings into the shared catalog:** its title, authors, first
  year, cover, and up to 20 editions (the scanned/chosen ISBN first, then
  editions with ISBNs). An existing shared work is reused when the provider ID
  or the wanted ISBN matches. Editions already in the catalog by ISBN are skipped.
- **Google Books, ISBNdb, and Hardcover** return editions, not works; each
  result is offered as a work with one edition. These three clients are written
  against their public API docs but untested here (they need keys); Open
  Library was tested live.
- **Covers** are stored as JPEG (quality 82) at 120, 300, and 600 px wide,
  named by the first 16 bytes (hex) of the original's SHA-256, under
  `<data_dir>/covers`, served at `/covers/<hash>-<s|m|l>.jpg` with year-long
  caching. Uploads are limited to 10 MB. Open Library's 1×1 "no cover" images
  are ignored.
- **Search result covers** go through `/api/catalog/thumb?u=…`, which only
  fetches from the providers' image hosts, so browsers never contact
  providers directly.
- **Rate limits** (in memory, per minute): catalog search 30 per user. More
  are added in milestone 8.
- **Similar-title check** for manual entries: shared works whose title
  contains, or is contained in, the entered title (ignoring a leading
  The/A/An), or shares a word of 5+ letters. Up to 5 are offered.
- **The barcode decoder** (zxing-wasm, about 950 KB) is bundled and loaded
  when the scanner opens. Its default CDN location is overridden, so it never
  loads from jsDelivr. The service worker does precache it with the rest of
  the app at install, so scanning works offline (the lookup that follows
  needs a connection).
- **Scanning** reads EAN-13 codes four times a second and accepts only
  978/979 (Bookland) codes, which are ISBNs.
- **A scanned or typed ISBN with exactly one match** opens the confirm sheet
  straight away.
- **Adding from search needs a connection** (the work must exist on the
  server first). Manual entry works offline; its similar-title check is
  skipped when offline.
- **A cover chosen during manual entry** becomes the book's cover override
  (only the creator sees the private work anyway).
- **"Add another copy" mode** (the book is already on your list) always
  records a copy; "I own a copy" isn't shown.

## Milestone 6: settings, sharing, import, export

- **Import parsing lives in `mau-core::import`** and is unit-tested with sample
  files. Column names follow each service's current export format.
- **What imports bring in:** title, authors, ISBN, pages, year, publisher,
  rating (rounded to whole stars), finished readings with their dates, tags,
  owned (one copy, with the file's binding, else Paperback), and notes.
  Notes combine the review and private notes (Goodreads: "My Review" and
  "Private Notes"; LibraryThing: review and comments).
- **Goodreads shelves** other than read/currently-reading/to-read become tags.
  A "Read Count" above 1 adds undated earlier readings.
- **LibraryThing:** books in the "Your library" collection (or in no
  collection) count as owned; "Read but unowned", "Wishlist", and "To read"
  don't.
- **Generic CSV:** a state value of read/finished/done/complete/yes/true/1/x,
  or a finished date, means finished; an owned value of yes/true/1/x/owned, or
  a positive number, means owned.
- **Unknown finish dates** are stored as `0000-01-01` and shown as "date
  unknown".
- **Imported finished readings** have total = the file's page count, else the
  catalog's, else 1, and no daily history (no progress events), so they don't
  add to calendars. mau's own JSON export restores the full history.
- **Matching an import row:** already on the list (same ISBN, or same title and
  author surname) → skipped; ISBN already in the shared catalog → matched to it;
  ISBN found by a provider → matched; else a title + first-author search, where
  an exact title and author match → matched, other results → "check match"
  with up to 3 candidates, none → "not found" (default: add as a private manual
  entry). Three rows are matched at a time.
- **Imported books go to the top of the inactive books**, in file order. A mau
  JSON import keeps books active if they were active with an unfinished reading.
- **Import jobs live in server memory** for up to 6 hours; at most 5,000 books
  and 30 MB per file, 5 imports a minute.
- **mau's JSON export** (`format: "mau-export", version: 1`) includes each
  book's work data (title, people, year, editions), overrides, rank, active,
  rating, notes, tags, copies (with edition ISBN), and readings with all
  progress events. Re-importing it reuses shared works by ISBN and otherwise
  creates private manual entries.
- **CSV export columns:** Title, Authors, State, Current page, Total pages,
  Started, Finished, Rating, Tags, Owned, Copies, ISBN, Notes.
- **Share links** are `/s/<22-character token>` (128 bits). Each kind of share
  (finished, active, the whole catalog, or a given tag) can exist once.
- **Settings → Account** holds display name, bio, username, time zone (any
  IANA zone, with a one-tap "use this device's zone" hint), appearance
  (per device), and account deletion.
- **Signing out with unsynced changes** asks first, saying how many changes
  will be lost (spec assumption 2). Signing out offline still deletes this
  device's copy.
- **CSV column mapping** is pre-filled by guessing from header names; each mau
  field can be mapped once.
- **Import review defaults:** matched rows are imported, "check match" rows
  take the first candidate, "not found" rows become manual entries, and books
  already on the list are skipped. Each can be changed before importing.

## Milestone 7: admin and public pages

- **Suspending a user signs them out everywhere** (their sessions are
  deleted); unsuspending lets them sign in again.
- **Admins can't delete their own account from the admin page;** that goes
  through Settings → Account (with its passkey confirmation).
- **Creating an enrollment link** also adds a note to the user's Recovery
  activity right away ("An admin (name) issued a one-time link…"), and another
  when it's used.
- **Invites:** admins see and can revoke all pending invites; when everyone
  may invite, other users see their own under Settings → Invites. Creating an
  invite while signup is closed is refused.
- **Provider API keys are never sent to browsers;** the admin page shows only
  whether a key is saved. Leaving the key field empty keeps the saved key.
- **Review queue actions:** "Add to shared catalog" (optionally edited first)
  makes the work and its editions shared; "Merge into existing" moves the
  owner's book to the existing shared work (copies keep their edition when an
  edition with the same ISBN exists there) and deletes the duplicate; "Decline"
  keeps it private. Possible duplicates are listed using the similar-title rule.
- **Shared catalog editor:** admins search shared works by title, author, or
  ISBN, edit title, people, year, and editions, and replace covers. Every edit
  bumps the work's change number, so the change reaches every device with the
  book on its list.
- **Public pages** are plain HTML with inline CSS and the app's self-hosted
  Newsreader font, cached for 60 seconds. They follow the visitor's light or
  dark mode. Suspended users' pages show "Nothing here". Finished books are
  ordered by finish date (newest first), tags and the whole catalog by date
  added, currently reading in the owner's manual order. The profile shows up to
  8 books per item with "See all N" linking to the item's own page.

## Milestone 8: hardening and release

- **Client IP behind a proxy:** when the direct peer is a trusted proxy, the
  client is the right-most `X-Forwarded-For` address that isn't a trusted proxy
  (so clients can't spoof by adding entries).
- **Rate limits per IP, per minute:** sign-in 20, recovery-code sign-in 5
  (plus 5 per username), registration 20, username checks 60, setup-link
  checks 10, invite and enrollment links 20 and 10. Limits are in memory and
  reset on restart. Over the limit: HTTP 429 "Too many attempts".
- **Security headers on every response:** `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: same-origin`, `X-Frame-Options: DENY`, and a
  `Permissions-Policy` that allows only this site to use the camera (for
  scanning). No Content-Security-Policy yet: it needs care around the app's
  inline styles and should be added deliberately.
- **Backups:** checked hourly; when the newest snapshot in `<data_dir>/backups`
  is a day old or missing, a new `mau-YYYYMMDD-HHMMSS.db` is written with
  SQLite's `VACUUM INTO` (consistent, safe while running), and the newest
  `backup_keep` (default 7; `0` turns them off) are kept. `mau backup PATH`
  makes a one-off copy. Cover images aren't copied; back up `<data_dir>/covers`
  with your own tools.
- **Clippy's "complex type" lint is allowed in `mau-server`:** many queries read
  rows into tuples directly; naming each tuple type would add indirection
  without clarity.
- **The release binary links the system C library dynamically** (glibc), and
  is built for the machine it's built on. Fully static (musl) and arm64 builds
  aren't set up yet; they'd need the musl and aarch64 Rust targets plus a cross
  C toolchain for the TLS library. (Superseded: CI builds a static musl
  binary; see "Hosting maubooks.org".)
- **Generated API types are excluded from prettier**, so `cargo test` and
  `npm run format` don't fight over their formatting.
- **End-to-end tests** cover the first-admin signup and passkey sign-in, +1 and
  undo, offline taps syncing later, pausing, and the catalog and detail page.
  They share one server and run in file order; the signup test saves its
  session for the others.
- **Installable app:** a web app manifest with a teal open-book icon (SVG,
  192 and 512 px PNGs, a maskable version, and an Apple touch icon), theme
  color deep teal, standalone display.
- **Offline covers:** after each sync that changes books or works, the small
  (120 px) and medium (300 px) covers of every book on the list are fetched
  into the service worker's cover cache, three at a time. Large (600 px)
  covers aren't kept offline (spec assumption 1: thumbnails, not full size).
- **Runtime check in Firefox:** the system Firefox (153 ESR) was driven
  headless through Puppeteer and WebDriver BiDi, with a session cookie
  instead of a passkey. That run found and fixed three bugs: duplicate ISBNs
  crashing the add sheet (editions are now keyed by position), the sheet
  overflowing on phones, and search-result covers never loading.

## After launch

- **Security keys without a PIN are refused** (user choice, 2026-11-08). A new
  YubiKey made a passkey without user verification and webauthn-rs rejected
  it. mau keeps requiring user verification, since a passkey is the only way
  to sign in. Registration now answers with a clear message ("Set a PIN on the
  key, then try again", code `passkey_no_pin`), and the README explains how to
  set a PIN.
- **Passwords replace passkeys** (user choice, 2026-11-08). The security key
  on hand couldn't be given a PIN, and the user chose username and password
  with optional authenticator-app two-factor instead. webauthn-rs and the
  passkey screens are gone. The answers they gave:
  - Forgotten password: a recovery code (from signup) sets a new one, or an
    admin's one-time reset link, or `mau reset-password <username>` on the
    server.
  - Password rules: 10–256 characters, not a common password, not the
    username. Argon2id.
  - Lost authenticator: a recovery code works in place of a code; reset links
    also turn two-factor off.
  - Confirming sensitive actions: password, plus a code when two-factor is on.
- **The common-password list is the UK NCSC's top 100,000**, not the 10,000
  list proposed. Only entries of 10+ characters matter (shorter ones are
  refused anyway), and the 10,000 list has just 51 of them. The NCSC list has
  9,126, which is about 106 KB in the binary.
- **Confirmation lasts 10 minutes**, up from the 5 used for passkeys. The
  question put to the user wrongly said 10 was the existing value; 10 is what
  they approved, so it's 10.
- **Two-factor codes:** TOTP, SHA-1, 6 digits, 30 seconds, one step of drift
  either way. The last accepted step is stored per user, so a code can't be
  used twice (including the one that turned two-factor on). Setup must be
  confirmed with a code within 5 minutes. The app label is "mau (host)".
- **Sign-in with two-factor is two requests.** A right password returns a
  ticket (kept in server memory for 5 minutes, at most 5 wrong codes); the
  code goes with the ticket. A restart means signing in again.
- **Wrong usernames and wrong passwords get the same answer**, and an unknown
  account still costs one Argon2 check, so answers don't reveal which
  usernames exist. The username check on signup still does, as before.
- **Rate limits:** sign-in 20 per minute per address and 10 per account;
  password confirmation 10 per address and 5 per account; recovery 5 per
  address and per account; reset links 10 per address.
- **Setting a password through recovery signs out every device**, then signs
  in the one in use. Changing it in Settings signs out nothing; Sessions can.
- **A recovery code leaves two-factor on; a reset link turns it off.** With a
  code the person still has their recovery material; a reset link is for
  people who have lost everything.
- **Only the newest reset link works.** Issuing one voids earlier unused ones.
- **Migration 0006 rebuilds `users`** (to drop the unique `webauthn_id`
  column) and drops `passkeys`, `enroll_links`, and `sessions.restricted`.
  Accounts from the passkey era have no password; they need a reset link.
- **The Playwright sign-up test now uses a password**, so it no longer needs
  Chromium's virtual authenticator. It's still unrun here (no Chromium). The
  same flows were run in Firefox: sign-up, sign-in, turning on two-factor, a
  code at sign-in, a recovery code at sign-in and in confirmation, changing the
  password, recovery, and a reset link from the command line.

### dinky.dev import (2026-11-08)

- **User choices:** archived items are finished with an unknown date, active
  ones inactive; trailing (…) notes are ignored when matching only; dinky's
  `created` becomes the added date; no source tag. Deleted items are left out
  (the request).
- **It's a regular import source** ("dinky.dev (JSON)" in Settings → Import),
  with the usual review, rather than a one-off command.
- **Order:** unfinished books newest-created first and finished ones
  newest-updated first, as dinky's library lists them; the Reading view keeps
  that order.
- **Parsing:** the line splits at the first `|`; authors split on `;`; a
  Markdown link `[text](url)` keeps its text; whitespace (including
  non-breaking spaces) is trimmed. A line without `|` is a title with no
  authors. dinky's `today` reminders are ignored.
- **Notes stripping is for dinky only.** Goodreads titles carry the same
  "(Series, #2)" notes and would match better too, but that wasn't asked for.
  Duplicate checks compare both the full and the stripped title, so a second
  import of the same file skips everything.
- **Other importers still use the import time as the added date**, though
  Goodreads and StoryGraph files have a Date Added column.

### Import search, own Google Books key, background saving (2026-11-08)

- **Test run first:** the user's 1,020 dinky books against Open Library
  matched 781, left 101 to check and 138 not found. Open Library needs every
  query word in a record: middle initials ("Ernst W Mayr"), "CPA", subtitles,
  and hyphens or apostrophes next to an author ("Data-Intensive …
  Kleppmann", "Don't … Steve Krug") return nothing. Short title + surname with
  punctuation removed found 80 of the 138 exactly and 22 loosely; 36 aren't
  in Open Library at all. Keyless Google Books couldn't be tried (the shared
  quota was used up).
- **User choices:** each user adds their own Google Books key (Settings →
  Google Books); it's used for imports and for the Add page search, which
  then asks Google only. Without one, imports use Open Library, even if the
  admin set a server Google key. The fallback search runs whenever the first
  has no clear match, for every import source. Review rows can be edited and
  searched again. If Google refuses, Open Library answers for that book.
  Google results take Open Library's large cover by ISBN first. Saving runs
  in the background.
- **A clear match** is the same normalized title (no trailing notes, no
  subtitle after ":", no leading The/A/An, letters and digits only) and the
  first author's surname among the result's authors. The surname is the last
  word before any comma, so "Bird, Richard" and "Mike Piper, CPA" both work.
  This normalization now also applies to duplicate checks for every source.
- **Imports use Open Library only if the admin hasn't turned it off.** With it
  off and no own key, nothing is searched and rows come in as not found.
- **Up to three requests per book** (ISBN, first search, fallback); the
  fallback is skipped when it would be the same query. Check-match rows offer
  up to 10 results from both searches.
- **Refusals** are counted per book; review shows the count and Google's
  latest message. Google's error text is now passed through ("Google Books
  refused: API key not valid…") instead of only the HTTP status.
- **The key** is stored in plain text in `users.google_books_key` (like the
  admin's provider keys), checked with one search for "dune" before saving,
  shown back only as its last 4 characters, and limited to 10 saves a minute.
  Changing it doesn't need a password confirmation. `Me.google_books` drives
  the Settings row ("Own key" / "Off").
- **Re-search** (`POST /api/import/{job}/rows/{index}`) skips the ISBN step
  and the duplicate check, allows 30 a minute, and replaces the row's title
  and authors. It isn't allowed once saving has started.
- **Background saving:** `commit` returns at once; the status reports
  "n of m" (books processed in the catalog phase, which is the slow part:
  12¾ minutes for the test file, almost all fetching editions and covers),
  then the result or the error. A job being saved is never pruned or
  dismissed. `GET /api/import/current` gives the user's newest job so the page
  resumes; Done or Cancel drops it (`DELETE /api/import/{job}`). Catalog
  works are still added one at a time, to avoid two rows racing to add the
  same work.
- **Covers by ISBN** try at most two of the result's ISBNs at
  `covers.openlibrary.org/b/isbn/{isbn}-L.jpg?default=false`, then Google's
  thumbnail. This applies wherever a Google result is added (import or Add).

## Audit and threat model (2026-11-09)

The audit and its findings are in docs/THREAT_MODEL.md (STRIDE, OWASP risk
rating). Chosen by the user:

- **Code lockout with a warning:** 10 wrong second-factor codes (authenticator
  or recovery) for an account within an hour block codes for 15 minutes, and
  a recovery-activity line tells the owner someone had their password.
- **A password change signs out every other device** (this one stays).
- **One import in progress per user** (matching or saving); a second start
  gets 409 "Finish or cancel your current import first." An import waiting in
  review doesn't block a new one.
- **Profiles with nothing published return the not-found page** (spec §9
  changed).

Fixed without asking, as plain hardening (no visible behavior change):

- The data directory is set to mode 700 on every start (all commands), with
  a log line when it changes. README: `install -d -m 700`, OpenRC `umask=077`,
  systemd `UMask=0077` plus NoNewPrivileges, ProtectSystem=strict,
  ProtectHome, PrivateTmp, ReadWritePaths.
- Image decoding: 10,000 px a side, 256 MB allocation, two decodes at once
  (a semaphore).
- Outbound HTTP (providers and covers): redirects only to https domain names,
  never IP literals or localhost, at most 5. Cover bodies are read in chunks
  and dropped past 10 MB.
- Sync: IDs of new records must be 1–64 characters of `[A-Za-z0-9_-]`; cover
  overrides must be a 32-hex stored hash or empty.
- Content-Security-Policy on every response: `default-src 'self'`; scripts
  from self plus the SPA shell's inline script by SHA-256 (computed at start
  from the embedded 200.html) and `'wasm-unsafe-eval'` for the barcode
  decoder; inline styles allowed (Svelte style attributes, public pages);
  images from self, data: (QR code) and blob:; `frame-ancestors 'none'`,
  `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`.
- HSTS `max-age=31536000` when `public_url` is https (no includeSubDomains or
  preload, so other hosts on the domain aren't affected).
- Lockout columns: `users.code_failures`, `code_failures_since`,
  `code_locked_until` (migration 0008). A reset link clears them along with
  two-factor. The lockout applies to sign-in codes and to confirmations.

Not fixed (recorded as residual risk in the threat model): the bundled SQLite
advisory (sqlx 0.9 caps libsqlite3-sys below the patched 0.39); a dev-only
npm advisory; plain-text TOTP secrets and API keys at rest.
