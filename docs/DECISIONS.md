# Implementation decisions

Choices made while building mau that the spec (`docs/SPEC.md`) doesn't settle.
Each entry says what was chosen and why, so any of them can be revisited.
Newest entries at the bottom of each section.

## Milestone 1: skeleton

- **Port 8370** is the default listen port (`127.0.0.1:8370`).
- **Config lookup:** `--config`/`MAU_CONFIG`, else `/etc/mau/mau.toml` if it
  exists, else built-in defaults. Unknown keys are an error. `public_url` must
  be `https://…` or `http://localhost…` (passkeys need a secure context).
- **Development data** lives in `./data` (git-ignored).
- **Logging** via `MAU_LOG` (tracing env-filter syntax), default `info`.
- **Release profile:** thin LTO, one codegen unit, stripped.
- **SPA shell** is `200.html` (adapter-static fallback). The server serves
  matching embedded files, else the shell. `_app/immutable/*` is cached for a
  year; everything else `no-cache`.
- **Crates:** `mau-core` (pure domain logic, no I/O) and `mau-server` (binary
  `mau`).
- **npm audit** reports low-severity `deepmerge` advisories via
  `@sveltejs/adapter-static` (build-time only, not shipped). Left as is.

## Architecture (decided before milestone 2)

- **IDs** are UUIDv7 strings, generated by whichever side creates the record
  (clients create books, readings, copies offline).
- **Hybrid logical clock (HLC):** timestamps are strings
  `"{ms:013}-{counter:04}-{node}"`, so plain string comparison orders them.
  `node` is a random per-device ID (`srv` for the server).
- **Sync = operation log with field-level last-writer-wins.** Every synced row
  keeps a per-field clock (JSON column). A `set` operation updates a field only
  if its HLC is newer than that field's clock. Deletes are tombstones; later
  operations on a tombstoned row are dropped.
- **Progress uses a fork-aware rule** (to get "latest position wins, and the
  losing device's taps vanish"): each progress operation carries the HLC of the
  position it started from (`base`). If its HLC is older than the current
  position's, it's dropped. If `base` matches, it's appended. If `base` is
  older (the other device moved on meanwhile) and this operation is newer, the
  events recorded after `base` are deleted before appending.
- **Pull** uses a per-user change sequence: every row change bumps a global
  `seq`; clients ask for rows with `seq > last_seen`.
- **Manual ordering** uses fractional-index strings (`rank`), compared as
  plain strings. The display is active books by rank, then inactive by rank, so
  "end of active" and "top of inactive" are just ranks after the last active or
  before the first inactive.
- **The browser keeps the whole library in IndexedDB** and renders from it;
  the server is only needed for catalog search, ISBN lookup, import, admin,
  and sharing changes.
- **Public profile and share pages are rendered on the server** (HTML, no
  JavaScript needed) so search engines can index them, using the `maud` crate.
- **API types** are generated from Rust into TypeScript with `ts-rs`.

## Milestone 2: authentication

- **Discoverable passkeys are required at registration.** webauthn-rs's
  `start_passkey_registration` asks for `residentKey: "discouraged"`; mau
  rewrites that to `"required"` before sending it to the browser. Without this,
  hardware keys like YubiKeys create non-discoverable credentials that the
  username-less "Sign in with a passkey" button can't use.
- **Sign-in is a modal prompt, not autofill.** webauthn-rs's
  `start_discoverable_authentication` sets `mediation: "conditional"`
  (autofill UI); mau clears it so the button opens the normal passkey prompt.
- **Ceremony state** (in-progress registrations and sign-ins) is kept in
  server memory for 5 minutes, keyed by a random challenge ID. A restart
  during a sign-in just means trying again.
- **Session cookie:** `mau_session`, 32 random bytes, base64url. Only its
  SHA-256 is stored. `HttpOnly`, `SameSite=Lax`, `Secure` unless `public_url`
  is `http://localhost`. The 30-day expiry is extended at most once an hour.
- **CSRF:** besides SameSite, every non-GET `/api` request must carry an
  `Origin` header matching `public_url`.
- **"Fresh passkey" for sensitive actions** means the session confirmed a
  passkey within the last 5 minutes (`/api/auth/reauth`).
- **Recovery codes:** format `xxxxx-xxxxx` from a 31-letter alphabet without
  look-alikes (no 0/o/1/l/i), about 49 bits each. Stored as Argon2id hashes.
- **Tokens** (invites, setup link, admin enrollment links) are 32 random bytes;
  only SHA-256 hashes are stored. The setup token exists only in memory.
- **A recovery-code sign-in** creates a restricted session that can only add a
  passkey; it becomes a normal session once one is added. The same applies to
  admin-issued enrollment links.
- **Device labels** for sessions and suggested passkey names come from the
  User-Agent ("Firefox on Linux").
- **Passkey ceremonies aren't unit-tested end to end.** webauthn-rs's soft
  authenticator can't create discoverable credentials, so the full
  register/sign-in flow is covered by Playwright with Chromium's virtual
  authenticator (milestone 8). API tests cover everything around it.
- **Generated TypeScript types** go to `web/src/lib/api/generated/` (set in
  `.cargo/config.toml`), refreshed by `cargo test`. They're committed so the
  web app builds without running Rust tests first.
- **Deleting the last admin's account is refused** ("make someone else an
  admin first"), extending the spec's "last admin is protected" to self-deletion.
- **Imports use explicit extensions** (`#lib/api/client.ts`), as the SvelteKit
  3 template's `package.json` "imports" mapping requires. ts-rs is told to
  emit `.ts` extensions too (`TS_RS_IMPORT_EXTENSION`).
- **End-to-end tests start their own server** on port 8371 with a temporary
  data directory, and read the setup link from its log. They use Chromium
  (Playwright) because only Chromium offers a scriptable virtual authenticator.
- **Who's signed in is cached in localStorage** (`mau.me`) so the app opens
  offline; the server's answer always wins when it's reachable.
- **Routes:** signed-out pages under `src/routes/(public)`, the app under
  `src/routes/(app)` with the tab bar (bottom on phones, left sidebar from
  900px wide).

## Milestone 3: library, sync, Reading view

- **Progress conflicts are judged per chain, not per tap.** A device's unsynced
  progress changes form a chain (each one's `base` is the previous one's
  clock). The server judges the whole chain by its newest change against the
  current position: older chains are dropped whole; newer chains that branched
  from an older position replace the other branch's events after that point.
  Judging tap by tap would drop the early taps of a winning session.
- **Undo is an operation** (`progress.undo`) that removes the event it undoes
  and restores the position, so undone taps never count as reading.
- **One change number per sync request.** All rows a request changes share
  one `seq`, taken first so the transaction holds SQLite's write lock.
- **Each operation runs in a savepoint;** an invalid operation is rolled back
  and reported under `rejected`, and the device discards it. Operations about
  deleted or unknown rows, or with stale clocks, are `dropped` silently.
- **Removing a book** tombstones its readings, events, copies, and tags in
  the same operation (the spec's "permanently deletes"), and blanks its notes
  and rating. Tombstone rows stay so other devices learn about the removal.
- **Seed data:** `mau seed --user NAME` (or `just seed NAME`) adds the mocks'
  16 books with generated reading history. It refuses unless `public_url` is
  `http://localhost…`.
- **Dates for progress events** are computed by the device in the user's time
  zone setting and stored as `YYYY-MM-DD`.
- **Undoing "start reading"** deletes the new reading (`reading.delete`), so an
  undone start or re-read leaves no empty reading behind.
- **The browser keeps two layers:** the last data the server sent (in
  IndexedDB, one database per user: `mau-<user id>`) and the unsent
  operations (an outbox). The screen shows the server data with the outbox
  replayed on top, using the same rules as the server. After each sync the
  view is rebuilt from the server's answer plus whatever is still unsent.
- **Sync timing:** 0.8 s after the last change, when the browser comes back
  online, when the tab becomes visible, and every 60 s. Up to 500 operations
  per request.
- **A revoked session** (the server answers 401 to a sync) wipes this device's
  copy, including unsent changes, and goes to sign-in (spec assumption 3).
- **Rejected operations** are discarded and the first reason is shown in a toast.
- **The service worker** caches the app shell and assets at install, serves the
  cached shell for page loads when offline, and caches cover images as they're
  seen. It never caches `/api` (data lives in IndexedDB) or the server-rendered
  public pages (`/u/…`, `/s/…`). In SvelteKit 3 it's excluded from the main
  `tsconfig.json` and checked with `tsconfig.service-worker.json`.
- **"Today"** is computed in the user's time zone setting, not the device's.
- **Finished books leave the Reading view at once** (spec decision); the undo
  toast brings them back.
- **Status line:** the Reading header says "Offline · N unsynced" or
  "Syncing…" when relevant, and nothing otherwise.

## Milestone 4: catalog and book detail

- **Surname for the author sort:** the last word of the first author's name,
  plus particles directly before it (le, de, van, von, der, du, da, di, …), so
  "Ursula K. Le Guin" sorts under "Le Guin". "St." is a particle only when it
  comes right before the last word ("Emily St. John Mandel" sorts as "Mandel").
- **Catalog layout and sort** are remembered per device in localStorage
  (`mau.catalog.layout`, `mau.catalog.sort`); filters reset on each visit.
- **"‹ Catalog"** uses browser history when you came from the catalog, so its
  scroll position and filters are kept; otherwise it's a plain link.
- **Edit details** takes authors as one comma-separated field. Entering the
  catalog's own value clears that override instead of storing a copy.
  "Reset to catalog" clears title, authors, and cover overrides together.
- **Uploading a cover needs a connection** (the image goes to the server);
  title and author edits work offline.
- **Notes autosave** 0.7 s after typing stops.
- **Calendar shading** uses one teal ramp mixed from the accent color, so it
  follows light and dark mode automatically.
- **Daily summaries** merge consecutive forward moves on the same day into
  one line; any backward move is its own "moved back" line.
- **A re-read** starts with the previous reading's total; it can be changed
  by tapping the page count.

## Milestone 5: adding books, providers, covers

- **HTTPS client:** reqwest with rustls (aws-lc-rs) and the system's
  certificate store; needs `cmake` and a C compiler at build time.
  User-Agent `mau/<version> (+<public_url>)`, 20 s timeout.
- **Provider fallback:** enabled providers are asked in the admin's order;
  for a text search the next one is asked when fewer than 3 results came back
  ("thin"), and results are de-duplicated by title and first author, up to 20.
  For an ISBN, the first provider with a match wins.
- **Provider responses are cached 30 days** in `provider_cache` (search
  results, ISBN lookups, edition lists, and each offered search result).
  Adding a book uses the cached result, so clients can't inject catalog data.
- **What a work brings into the shared catalog:** its title, authors, first
  year, cover, and up to 20 editions (the scanned/chosen ISBN first, then
  editions with ISBNs). An existing shared work is reused when the provider ID
  or the wanted ISBN matches. Editions already in the catalog by ISBN are skipped.
- **Google Books, ISBNdb, and Hardcover** return editions, not works; each
  result is offered as a work with one edition. These three clients are written
  against their public API docs but untested here (they need keys); Open
  Library was tested live.
- **Covers** are stored as JPEG (quality 82) at 120, 300, and 600 px wide,
  named by the first 16 bytes (hex) of the original's SHA-256, under
  `<data_dir>/covers`, served at `/covers/<hash>-<s|m|l>.jpg` with year-long
  caching. Uploads are limited to 10 MB. Open Library's 1×1 "no cover" images
  are ignored.
- **Search result covers** go through `/api/catalog/thumb?u=…`, which only
  fetches from the providers' image hosts, so browsers never contact
  providers directly.
- **Rate limits** (in memory, per minute): catalog search 30 per user. More
  are added in milestone 8.
- **Similar-title check** for manual entries: shared works whose title
  contains, or is contained in, the entered title (ignoring a leading
  The/A/An), or shares a word of 5+ letters. Up to 5 are offered.
- **The barcode decoder** (zxing-wasm, about 950 KB) is bundled and loaded
  when the scanner opens. Its default CDN location is overridden, so it never
  loads from jsDelivr. The service worker does precache it with the rest of
  the app at install, so scanning works offline (the lookup that follows
  needs a connection).
- **Scanning** reads EAN-13 codes four times a second and accepts only
  978/979 (Bookland) codes, which are ISBNs.
- **A scanned or typed ISBN with exactly one match** opens the confirm sheet
  straight away.
- **Adding from search needs a connection** (the work must exist on the
  server first). Manual entry works offline; its similar-title check is
  skipped when offline.
- **A cover chosen during manual entry** becomes the book's cover override
  (only the creator sees the private work anyway).
- **"Add another copy" mode** (the book is already on your list) always
  records a copy; "I own a copy" isn't shown.

## Milestone 6: settings, sharing, import, export

- **Import parsing lives in `mau-core::import`** and is unit-tested with sample
  files. Column names follow each service's current export format.
- **What imports bring in:** title, authors, ISBN, pages, year, publisher,
  rating (rounded to whole stars), finished readings with their dates, tags,
  owned (one copy, with the file's binding, else Paperback), and notes.
  Notes combine the review and private notes (Goodreads: "My Review" and
  "Private Notes"; LibraryThing: review and comments).
- **Goodreads shelves** other than read/currently-reading/to-read become tags.
  A "Read Count" above 1 adds undated earlier readings.
- **LibraryThing:** books in the "Your library" collection (or in no
  collection) count as owned; "Read but unowned", "Wishlist", and "To read"
  don't.
- **Generic CSV:** a state value of read/finished/done/complete/yes/true/1/x,
  or a finished date, means finished; an owned value of yes/true/1/x/owned, or
  a positive number, means owned.
- **Unknown finish dates** are stored as `0000-01-01` and shown as "date
  unknown".
- **Imported finished readings** have total = the file's page count, else the
  catalog's, else 1, and no daily history (no progress events), so they don't
  add to calendars. mau's own JSON export restores the full history.
- **Matching an import row:** already on the list (same ISBN, or same title and
  author surname) → skipped; ISBN already in the shared catalog → matched to it;
  ISBN found by a provider → matched; else a title + first-author search, where
  an exact title and author match → matched, other results → "check match"
  with up to 3 candidates, none → "not found" (default: add as a private manual
  entry). Three rows are matched at a time.
- **Imported books go to the top of the inactive books**, in file order. A mau
  JSON import keeps books active if they were active with an unfinished reading.
- **Import jobs live in server memory** for up to 6 hours; at most 5,000 books
  and 30 MB per file, 5 imports a minute.
- **mau's JSON export** (`format: "mau-export", version: 1`) includes each
  book's work data (title, people, year, editions), overrides, rank, active,
  rating, notes, tags, copies (with edition ISBN), and readings with all
  progress events. Re-importing it reuses shared works by ISBN and otherwise
  creates private manual entries.
- **CSV export columns:** Title, Authors, State, Current page, Total pages,
  Started, Finished, Rating, Tags, Owned, Copies, ISBN, Notes.
- **Share links** are `/s/<22-character token>` (128 bits). Each kind of share
  (finished, active, the whole catalog, or a given tag) can exist once.
